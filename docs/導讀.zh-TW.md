# wisp 導讀（給初學者的白話版）

這份文件讓你能在面試時用自己的話講清楚 wisp：它解決什麼問題、關鍵想法是什麼、每個檔案在做什麼，
以及常被問到的問題怎麼回答。

## 它解決什麼問題？

WebAssembly（Wasm）是一種「可攜的機器碼」：C、Rust、Go 等語言都能編譯成 `.wasm` 檔，
然後在瀏覽器、伺服器、手機上跑，而且跑在沙箱裡、碰不到它不該碰的東西。
但 `.wasm` 檔本身不會自己動，需要一個「執行環境」（runtime）來讀懂它、檢查它、執行它，
並提供讀檔、印字、取時間這些系統功能（這套介面叫 WASI）。

wisp 就是這樣一個執行環境，從零寫起，包含：

1. **解碼器**：把 `.wasm` 的位元組讀成結構。
2. **驗證器**：在執行前證明程式「型別正確」，不會亂讀記憶體或跳到奇怪的地方。
3. **直譯器**：一道一道指令模擬執行。
4. **編譯器（JIT）**：把 Wasm 直接翻成 Apple M 系列晶片看得懂的 AArch64 機器碼來跑，快很多。
5. **WASI**：讓程式能讀寫檔案、拿參數、拿時間，但只能碰你允許的資料夾。

## 八個關鍵想法（附生活比喻）

### 1. 先驗證，再執行 —— 「上飛機前的安檢」
Wasm 的規則很嚴：每個指令吃什麼型別、吐什麼型別都定好了。驗證器用規格書附錄的演算法，
把整個函式「模擬推演」一遍，只看型別不看值。通過安檢的程式，執行時就不必再檢查型別，跑得更快也更安全。

### 2. 用固定槽位取代堆疊 —— 「每個人有固定座位的教室」
Wasm 原本是「堆疊機」：值不斷 push、pop，像疊盤子。但每個位置的堆疊高度在編譯時就知道，
所以 wisp 的直譯器乾脆替每個高度安排一個固定「座位」（槽位）。指令變成「把 3 號座位加 5 號座位，
放到 3 號座位」，不必搬盤子，速度就上來了。

### 3. 能拖就拖 —— 「點餐時先記下來，真的要做才去廚房」
`local.get` 在 wisp 裡不產生任何指令，只是記下「這個值其實在第 2 個區域變數那裡」；
常數也先記著，等真正需要時才寫進槽位。風險是：如果之後有人改了那個區域變數，記下的東西就過期了，
所以遇到 `local.set` 或進入區塊之前，會先把「欠著的」寫出來。

### 4. 單趟編譯 + 暫存器快取 —— 「邊聽邊做筆記的速記員」
編譯器只把函式從頭到尾讀一次，邊讀邊吐機器碼。它記得每個值目前在哪裡：在暫存器、在記憶體、
在 CPU 的比較旗標，或只是個常數。暫存器不夠時，把最早的值「暫存回桌上」（spill）。
這就是 V8 的 Liftoff、wasmtime 的 Winch 這類「基線編譯器」的做法：編譯很快，產生的碼還不錯。

### 5. 比較結果留在旗標裡 —— 「紅綠燈直接看，不必先寫在紙上」
`i32.lt_s` 算出「是否小於」，如果下一個指令就是「條件跳躍」，wisp 不會先把 0/1 存起來，
而是直接用 CPU 的比較旗標跳：`cmp; b.lt`，省下好幾道指令。

### 6. 陷阱就是「緊急出口」 —— 「火災時從安全門直接離開大樓」
Wasm 程式除以零、越界存取時要「陷阱」（trap），停止執行並回報錯誤。編譯後的程式碼一層層呼叫，
不可能每層都慢慢 return。wisp 的做法：進入編譯碼時先記下堆疊位置；出事時直接把堆疊指標「瞬移」
回那裡、恢復暫存器、帶著錯誤碼回到 Rust。因為編譯碼的框架不擁有任何資源，直接丟掉是安全的。

### 7. 邊界檢查 —— 「每次進倉庫前查一下編號有沒有超過倉庫大小」
Wasm 記憶體是一大塊連續位元組，程式只能用 0 到大小之間的位址。wisp 在每次讀寫前都比較一次
（`add; cmp; b.hi`）。另一種做法是在記憶體後面放一大片「地雷區」（保護頁），越界就讓作業系統抓到，
省下比較但很複雜。wisp 選簡單明確的版本，代價在效能表上看得到。

### 8. 能力式沙箱 —— 「只給你某間房間的鑰匙，而且門口有人確認你沒鑽地道」
客程式只能用「預先開放的資料夾」去開檔。wisp 解析路徑時一段一段走：遇到 `..` 就退回上一層，
退到最上層還想退就拒絕；遇到符號連結就自己讀它指向哪裡，再用同樣規則檢查。作業系統從來不替我們跟隨連結，
所以 `escape -> ../outside` 或指向 `/etc` 的連結都出不去。

## 面試常見問題

1. **直譯器和 JIT 差在哪？**
   直譯器每次執行都要「讀指令、判斷是哪一種、執行」；JIT 事先把整個函式翻成機器碼，執行時 CPU 直接跑。
   在 wisp 的測試中 JIT 快 3–8 倍，但要多花編譯時間。

2. **你怎麼證明它是對的？**
   跑官方規格測試，兩種引擎各 27,416 個斷言全過；真實 Rust 程式輸出和原生版本逐字相同；
   用 wasm-smith 隨機產生 5,000 個模組做直譯器對編譯器的差異測試，沒有不一致；編碼器和 clang 組譯結果逐字比對。

3. **為什麼不用保護頁做邊界檢查？**
   保護頁要攔截 SIGSEGV 訊號、從訊號處理器安全地跳出、和其他程式的訊號處理共存，很容易出錯。
   明確比較簡單、可攜、正確性一目了然；代價是記憶體密集的程式慢一些，效能表裡看得到。

4. **陷阱發生時，編譯碼裡的堆疊怎麼辦？**
   進入跳板會記錄堆疊指標；陷阱直接把 `sp` 設回去、恢復被保存的暫存器並回傳錯誤碼。
   編譯碼的框架裡沒有需要釋放的東西，所以直接丟掉是安全的。巢狀進入時會保存上一層的值。

5. **NaN 怎麼處理？**
   規格允許算術運算產生「算術 NaN」，ARM 硬體預設會保留輸入 NaN 的內容或產生標準 NaN，正好符合。
   `abs`、`neg`、`copysign` 是純位元操作，不改 payload。浮點數在 wisp 裡都以位元形式傳遞，不會被改掉。

6. **直譯器為什麼快？**
   固定槽位（不用 push/pop）、`local.get` 免費、立即值版本的指令、比較和跳躍合併、
   呼叫時被呼叫者的框架直接疊在引數上（不用複製）、wasm 之間的呼叫不在原生堆疊上遞迴。

7. **JIT 怎麼呼叫主機函式（例如 WASI）？**
   每個函式都有一個 `VmFuncRef`，裡面有程式碼位址。主機函式的位址指向一個共用的「慢速跳板」，
   它把函式參照與引數區傳給 Rust，Rust 執行完把結果寫回，再回到編譯碼。

8. **沙箱怎麼防止 `../` 和符號連結逃脫？**
   路徑一段一段用 `openat`/`readlinkat` 自己解析，`..` 只能退回自己開過的目錄，
   符號連結的內容由 wisp 讀出來再用同樣規則檢查，絕對路徑直接拒絕；最後一段用 `O_NOFOLLOW` 開。

9. **macOS 上產生機器碼有什麼特別？**
   Apple Silicon 不允許同一執行緒同時可寫又可執行同一頁。要用 `MAP_JIT` 申請記憶體，
   寫入前呼叫 `pthread_jit_write_protect_np(0)`，寫完再開回保護，並清除指令快取。

10. **還有什麼沒做？下一步是什麼？**
    沒有 SIMD、執行緒和 3.0 的新提案；編譯器沒有跨區塊的暫存器配置、區域變數不放暫存器；
    Linux 版本未測試。下一步會是保護頁邊界檢查和把常用區域變數留在暫存器裡。
